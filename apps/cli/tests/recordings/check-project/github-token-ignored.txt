5 things to do, in this order:
1 Sign in to GitHub
  keypin ignores GITHUB_TOKEN: it publishes only as a login gh has saved, so a token meant for another tool can't pick the account. Unset GITHUB_TOKEN, then run:
    gh auth login --hostname github.com --with-token < token.txt
  Use a classic token with the repo, read:org and gist scopes (gh needs all three), for alice.
2 Sign in to Cloudflare
    wrangler login
  Or set KEYPIN_CLOUDFLARE_API_TOKEN to a Cloudflare API token.
3 Set up 1Password
  keypin needs the 1Password desktop app, with Settings → Developer → Integrate with other apps selected.
4 Move .env's keys into 1Password
  .env sets DATABASE_URL, RESEND_API_KEY, which secretspec.toml doesn't declare.
    keypin import .env DATABASE_URL RESEND_API_KEY --vault <vault> --account <1Password sign-in address>
  Leave out a name that isn't a key; it stays in the file.
5 Add the production keys to secretspec.toml
  STRIPE_API_KEY: .github/workflows/deploy.yml uses it; acme/billing doesn't have it, and secretspec.toml doesn't publish it there.
  RESEND_API_KEY: wrangler.toml requires it; the Worker billing-worker doesn't have it, and secretspec.toml doesn't publish it there.
  If you ran the import above, run keypin check again for this TOML instead; the import wrote some of these tables.
